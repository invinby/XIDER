# TARPED 4.1.0 · X-DOCK / Guard Keeper

## Русский

4.1.0 — новая группа совместимых возможностей после 4.0.0: подписанная доставка
установщиков, локальное восстановление исходников и исправление перезапуска
macOS source-агента. Номер не является случайной датой или обещанием завершения
всего Mega-плана. Старые релизы сохраняются.

### Установка

macOS:

```sh
curl -fsSL https://invinby.github.io/XIDER/mac | bash
```

Windows PowerShell:

```powershell
irm https://invinby.github.io/XIDER/win.ps1 | iex
```

Короткие entrypoint требуют опубликованного GitHub Pages endpoint и файлов
этого релиза. Они проверяют подпись установщика; установщик проверяет подпись
bootstrap и полный commit. Windows-команда устанавливает Agent/Guardian,
не запускает деплой Telegram-сервера на VPS. Python/OpenSSH и первоначальный
SSH-доступ к серверу конфигурации обязательны. Разрешения ОС выдаются на устройстве.

### Изменения

- Mac обновляется из списка опубликованных подписанных source-релизов в боте.
  Одновременные обновления отклоняются. Перезапуск через `exec` устраняет конфликт
  singleton-блокировки со старым ещё работающим процессом.
- Старый процесс не может подтвердить здоровье новой версии своим переподключением.
  Новый worker проверяет исходники перед выбором recovery cache; журнал позволяет
  откатить и исходники, и выбор cache после прерывания.
- Guard Keeper восстанавливает отсутствующие allowlisted файлы из подписанного
  локального пакета, проверяя подпись, размер, SHA-256 и соответствие версии.
  Явная остановка/удаление не отменяются. Секреты и runtime не пересоздаются.
  Потеря worker во время незавершённой транзакции обрабатывается под общей
  singleton-блокировкой: сначала проверка журнала и откат согласованной версии.
- Зависимости initial Mac install готовятся до остановки старого агента.
  Runtime получает стабильный абсолютный путь; исходники прежней версии сохраняются.
- После здорового обновления worker уже загруженный Guardian перезапускается
  отдельно. Отключённая или отсутствующая задача при этом не включается.
- Ответы сценариев обоев используют текущую Telegram-карточку и шесть голосов
  X-LEX. Таймаут больше не выдаётся за установленный фон.
- Ошибки и промежуточный результат удаления описываются точно: исходники,
  `.env` и `agent.log` могут остаться после снятия автозапуска и локальных данных.
- Поздние ошибки перезапуска и удаления приходят владельцу отдельно с защитой
  от повторов. Ответ «удаление подготовлено» больше не отзывает права устройства
  до подтверждённого результата. Шесть стилей X-LEX сохраняют эту разницу.

### Ограничения

Это source-updater, не универсальное обновление PyInstaller-бинарников.
Изменение `requirements.txt` отклоняется до замены файлов; дистанционная
транзакционная замена Python runtime ещё не реализована. Рабочая MQTT-сессия —
не проверка камеры, экрана, геопозиции или каждого действия. Офлайн fixtures
не заменяют реальное испытание Mac/Windows и Telegram.

Guardian recovery требует живого Guardian и runtime. Полное удаление установки
не должно создавать скрытое восстановление. Имена `safari` и `siri` пока являются
предложениями ролей XIDER, не установленными службами Apple.

Подробности: [подготовка Mac](https://github.com/invinby/XIDER/blob/main/docs/MAC-REMOTE-UPDATES.md),
[Mega-план](https://github.com/invinby/XIDER/blob/main/docs/XIDER-MEGA-ROADMAP.md).

## English

4.1.0 is a compatible feature-group release after 4.0.0, not a random version
jump or a claim that the entire TARPED roadmap is finished. Previous releases
remain available.

- Short Windows/macOS entry points authenticate standalone installer hashes
  with the pinned publisher key. Each installer independently authenticates
  the bootstrap bound to the release tag and full source commit.
- Windows bootstrap is agent-only. macOS prepares dependencies before stopping
  the previous installation and keeps a stable runtime path and rollback copy.
- macOS source updates are serialized and restart via `exec`, avoiding the
  singleton race with a still-running parent. Only the new startup attempt can
  commit health; source files and recovery selection roll back together.
- Guard Keeper restores missing allowlisted files from a reverified signed
  local source package. Explicit stop/uninstall is respected; secrets and
  Python runtimes are not regenerated. A healthy worker update reloads only an
  already-loaded Guardian job, never enables an absent/disabled job.
- Wallpaper commands reuse one Telegram card, support six X-LEX voices and
  distinguish verified success from an unacknowledged request.
- Late restart/uninstall failures notify the owner with bounded duplicate
  suppression. A prepared uninstall reply no longer revokes device identity.
  A missing worker during a pending update triggers validated rollback under
  the shared singleton lock before the signed recovery cache is used.

Known limitations: changed dependencies require the installer; frozen packages
do not use the source updater; OS permissions require local consent; runtime,
Guardian removal and all-device deletion cannot be recovered by this cache.
Offline tests do not establish real-device camera, screen, location or power
functionality. See the roadmap for open acceptance checks.
