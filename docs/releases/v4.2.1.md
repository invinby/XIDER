# TARPED 4.2.1 · X-LATCH — agent recovery and atomic switching

## English

This patch release closes two upgrade-path gaps: compatible devices now have
an install action beside each release in the catalogue, legacy devices have a
visible owner-only recovery route, and Windows staged installation no longer
relies on recursive moves while agent processes may still hold files open.

- **X-LEDGER install action:** Compatible agents show an install button beside
  each release in the catalogue; selecting one still requires confirmation and
  the agent verifies the signed release before replacing files.
- **X-LATCH recovery:** The catalogue and version details for an old, frozen,
  untrusted, or offline agent now offer the owner a signed one-line bootstrap command. The
  command must be run in a terminal on that device; it is local bootstrap, not
  remote installation. The screen explicitly says it installs the latest
  signed release, not the historical version currently being viewed. After the
  agent reconnects, the owner can return to X-LEDGER and choose a compatible tag.
- **Windows atomic switch:** The installer waits for scheduled tasks, detects
  only the managed XGENT-WDS executable or the two agent scripts under the
  installation directory, and stops only those remaining processes. It then
  uses same-volume directory renames for activation and rollback.
- **Version identity:** Bot, Windows agent, macOS agent, and Windows PE metadata
  are aligned at 4.2.1.

Automated checks cover legacy-catalog recovery and Windows install/rollback
fixtures. Activation and rollback are two atomic directory renames with a brief
gap; if interrupted between them, the previous checkout remains in its backup
directory. These checks do not prove Telegram operation or physical-device
acceptance.

## Русский

Патч закрывает два провала в обновлении: у совместимого агента появляется
кнопка установки рядом с каждым релизом, у старого устройства — понятный
владельцу путь восстановления, а Windows-установщик перестаёт рекурсивно
переносить папку, пока процессы агента держат файлы открытыми.

- **Установка из X-LEDGER:** Рядом с каждым релизом для совместимого агента
  есть кнопка установки. Перед отправкой команды бот просит подтверждение, а
  агент проверяет подпись релиза до замены файлов.
- **Восстановление X-LATCH:** В каталоге и карточке старого, замороженного,
  недоверенного или офлайн-агента владелец получает короткую команду подписанного
  установщика. Её нужно выполнить в терминале именно на этом устройстве: это
  локальная установка, а не удалённая команда из Telegram. Текст уточняет, что
  ставится последний подписанный выпуск, а не исторический тег, открытый в
  каталоге. После подключения через X-LEDGER можно выбрать совместимый тег.
- **Атомарное переключение Windows:** Установщик дожидается остановки задач,
  находит только XGENT-WDS.exe или два скрипта агента внутри управляемого
  каталога и останавливает только найденные процессы. Установка и откат
  используют атомарное переименование папок на том же диске.
- **Версия:** исходники бота и обоих агентов, а также метаданные Windows PE
  согласованы на 4.2.1.

Автоматические проверки покрывают восстановление старого агента и фикстуры
установки/отката Windows. Две атомарные операции переименования разделены
коротким промежутком; при прерывании между ними прежняя версия остаётся в
резервной папке. Эти проверки не заменяют приёмку на физических устройствах.
