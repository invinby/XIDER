# XIDER UI and Agent Stabilization Plan

**Goal:** Make the Telegram device UI compact and predictable, make agent command outcomes honest, and verify the Windows/macOS install, update, diagnostics, storage, and package-protection flows against the current source.

**Additional owner goal:** Add a dedicated, owner-only **Agent Files** area for a clear inventory of the installed XIDER Agent, Guard Keeper, Safari, Siri, and related components. Show only verified metadata (component name, install path, version, size, hash, signature/integrity result, obfuscation-build status, and evidence time), with per-component details and safe navigation. The panel must distinguish “obfuscation step ran in the signed release build” from “unknown/not obfuscated”; it must not claim source secrecy or tamper-proofing. Keep file inspection transparent and owner-controlled. Do not hide files/processes, obstruct stopping or uninstalling, run arbitrary packers against installed files, or fetch/execute an unverified replacement. Any approved package transformation belongs in the reproducible release pipeline, with a signed manifest and an inspectable original source.

**Architecture:** Keep callback authorization and feature availability sourced from the existing registry and access store. Group device-catalog actions behind a dedicated submenu; keep device selection visible. Track platform behavior separately for bot, Windows, and macOS, and show unsupported or unverified states instead of inferred success.

**Tech Stack:** Python, aiogram, JSON feature registry, pytest, Windows PowerShell installer/agent, macOS shell installer/agent, GitHub Actions releases.

**Spec:** `C:\Users\invin\.codex\attachments\7f1f0d66-a597-4bde-98ec-bfd40bbdf35d\goal-objective.md`

## Global Constraints

- Preserve existing user configuration and untracked workspace files.
- Do not report a device action as successful solely because a command was sent.
- Keep device/callback authorization checks in place when regrouping navigation.
- Never label a build obfuscated, signed, or integrity-verified without evidence.
- Keep owner-visible inventory, diagnostics, logs, uninstall, and rollback available.
- Do not publish a release or change the live server without separate owner confirmation.
- Physical Windows/macOS behavior remains unverified unless exercised on those devices.

## Review Focus

- A user with only a subset of device grants must still reach the new catalog submenu without gaining other actions.
- Back navigation with no selected device, a stale selected device, and a selected device must land on the correct prior screen.
- Missing, stale, unsupported, malformed, or timed-out agent replies must never render as confirmed success.
- Installer rollback and version selection must preserve local `.env`, logs, and user-managed data.
- Inventory and cleanup must avoid exposing secret contents or deleting configuration and recovery artifacts.
