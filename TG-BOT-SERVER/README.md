# XIDER — TG-BOT-SERVER 4.1.7 TARPED

Telegram-бот, через который вы управляете своими устройствами.
Владелец задаётся `ADMIN_ID` в `.env` и не может быть заблокирован через базу
пользователей. Новые аккаунты начинают с роли гостя; владелец отдельно выдаёт
роль пользователя и доступ к конкретным кнопкам и устройствам.

## Установка и запуск

Требуется Python 3.10+.

```powershell
py -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python bot.py
```

Для macOS/Linux аналогично, но с `python3 -m venv venv`.

## Настройка

Секреты и параметры — в `.env` (скопируйте из `.env.example`):

| Параметр | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота от @BotFather |
| `ADMIN_ID` | Telegram ID владельца; только владелец открывает админ-раздел и имеет полный доступ |
| `SHARED_KEY` | Секрет HMAC-подписи — **должен совпадать** в XGENT-MCS и XGENT-WDS |
| `MQTT_BROKER` / `MQTT_PORT` | Приватный брокер; порт TLS по умолчанию `8883` |
| `MQTT_PREFIX` | Префикс топиков (xgent/v1) |
| `MQTT_TLS` | Обязательно `true`; plaintext MQTT запрещён |
| `MQTT_USERNAME` / `MQTT_PASSWORD` | Обязательные учётные данные приватного брокера с ACL |

Файл `known_devices.json` создаётся автоматически при первом подключении
клиента; устройства можно переименовать или удалить из списка прямо в боте.
Действия бота пишутся в `audit.log` (ротация, без секретов).

## Навигация и основные действия (v4.1.7)

Ниже — обзор, а не гарантия работы каждой команды на каждом устройстве.
Фактическая поддержка и статус по ОС фиксируются в X-MAP и в описании релиза;
информационные страницы доступны по роли, а управляющие кнопки зависят от
назначенных владельцем прав, выбранного устройства и разрешений ОС.

Роль определяет уровень доступа: **владелец** управляет ботом и устройствами;
**пользователь** получает только назначенные владельцем действия и устройства;
**гость** может просматривать доступные информационные страницы; **заблокированный**
аккаунт не может пользоваться ботом. Права проверяются повторно при обработке
отложенного ввода, а не только при нажатии исходной кнопки.

- `/start` — 🏠 Главная: 📱 Устройства / 🖥 Все устройства / 🔔 События
- `/cancel` — отмена текущего ввода (ссылка/текст/терминал/программа)
- Владелец: **Устройства → Установка · одна команда** — выбрать macOS или Windows
  и получить копируемую строку установки из подписанной GitHub Pages-точки входа.
- Если установленная версия ещё не умеет безопасно обновляться из бота, кнопка
  обновления покажет ту же подписанную команду для нужной ОС вместо неработающего
  удалённого обновления; запуск остаётся явным действием владельца.

Меню устройства разбито на категории (⬅️ Назад на каждом экране):

| Категория | Что внутри |
|---|---|
| 📸 Медиа | Скриншот, вебка, микрофон (5/15/30/60 с), озвучка, буфер (чтение/запись), громкость |
| 🖥 Система | Процессы (топ-15, пагинация, 🔪 kill по кнопке), диски, батарея, сеть, службы, sysinfo, возможности |
| 🎛 Управление | Ссылка, текст, запуск программы, терминал (с подтверждением) |
| ⚡ Питание/Защита | Блокировка, mute, **Wake-on-LAN**, сон, перезагрузка, выключение, автозапуск |
| ⚙️ Устройство | Переименовать, удалить, 🕘 история команд с «повторить», ⭐ избранное |

- **⭐ Избранное** — свои быстрые кнопки вверху меню устройства
- **🔔 События** — уведомления: «вернулся онлайн», «ушёл в оффлайн» (по LWT), батарея <20%
- **🖥 Все устройства** — сводка «ответили N/M» и массовые действия
- Шапка меню показывает статус: `🟢 ASUS · онлайн`

## XIDER Guardian

### English

The **Guardian** panel is available under **Device → Power & Protection**.
It talks to the platform supervisor and provides status, worker start, worker
stop, restart, and opt-in automatic recovery. The VPS heartbeat/LWT watchdog
remains independent, so the owner is notified when a device disappears.
The panel does not pretend that software can power on a discharged laptop.

### Русский

Раздел **Guardian** находится в **Устройство → Питание & Защита**. Он
управляет локальным supervisor на Windows или Mac: показывает состояние,
запускает, останавливает и перезапускает рабочий агент, а также включает автовосстановление.
VPS отдельно следит за heartbeat/LWT и уведомляет, если устройство пропало.
Выключенный или разряженный ноутбук программно включить нельзя — бот показывает
последнее время связи.

## Безопасность

- Все сообщения подписаны HMAC-SHA256 (общий ключ `SHARED_KEY`).
- Каждое сообщение содержит уникальный `nonce` — повторная отправка того же
  пакета отклоняется (anti-replay).
- Окно воспроизведения — 120 секунд (сообщения старше игнорируются).
- Используйте приватный MQTT-брокер с TLS и настройте на нём ACL только для
  топиков XIDER. Сейчас bootstrap передаёт одну пару broker credentials всем
  компонентам; отдельные учётные записи/права для бота и каждого устройства
  остаются задачей и не проверяются клиентами.
  Все три компонента отказываются запускаться с `MQTT_TLS=false` или без
  MQTT-логина и пароля.
- Отвал клиента виден боту мгновенно: клиенты публикуют LWT «offline».
- MQTT-команды Guardian и ответы на них доставляются с QoS 1.

⚠️ **Токен бота был показан в переписке.** Если есть подозрение на утечку —
выполните `/revoke` в @BotFather, затем `/token` и вставьте новый токен
в `.env`.
